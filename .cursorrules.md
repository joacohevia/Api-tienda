# .cursorrules

# Archivo de reglas persistentes para Cursor AI

# IDENTIDAD TÉCNICA DEL PROYECTO (declarar siempre al inicio):
Stack: PHP, MySQL
Arquitectura: Modelo-Vista-Controlador (MVC) puro, sin frameworks
Objetivo: Gestión de una base de datos con las tablas que estan en el diagrama de tienda[ref]: tiendaropa.sql

# Es muy importante NO sugerir librerías externas, paquetes de terceros ni frameworks de ningún tipo
# El código y ejemplos deben atenerse estrictamente a PHP y MySQL puros.
# No uses ningún ORM ni soluciones automáticas, todo acceso a base de datos debe realizarse usando sentencias SQL directas desde PHP.
# La estructura de archivos y directorios debe seguir el patrón MVC clásico: separar claramente modelos, vistas y controladores.
# No emplear patrones avanzados o arquitecturas que requieran código fuera de la lógica MVC tradicional.

# Instrucciones Básicas:
- Sigue siempre las reglas definidas en este archivo antes de cualquier otra indicación.
- Mantente consistente con el estilo de codificación del proyecto.
- No repitas información ya contenida en el código o documentación existente, salvo que sea estrictamente necesario.
- Si tienes dudas, consulta la documentación del proyecto o pregunta explícitamente antes de hacer suposiciones.
- Los cambios en este archivo deben ser verificados y consensuados por el equipo cuando sea posible.
-Cuando la tarea requiera crear o modificar controladores, modelos o vistas, lee primero la skill en skils/php-mvc-expert.md para asegurar que sigues la arquitectura de nuestro proyecto

# Formato de Código:
- Usa el estilo estándar de PHP para sangría (4 espacios).
- Añade comentarios explicativos donde la lógica no sea explícita.
- Añade PHPDoc a todas las funciones y clases públicas.
- Mantén el código modular y evita duplicación innecesaria.

# Buenas prácticas:
- Prioriza la legibilidad sobre optimizaciones prematuras.
- Escribe código autoexplicativo y acompañalo de comentarios solo cuando sea imprescindible.
- Prefiere nombres descriptivos para variables, funciones y clases.
- Implementa pruebas para cada nueva funcionalidad agregada al proyecto.

# Restricciones:
- No generes datos sensibles o credenciales en ejemplos o pruebas.
- No incluyas dependencias innecesarias.
- Cumple con las políticas de seguridad y privacidad del equipo/proyecto.
